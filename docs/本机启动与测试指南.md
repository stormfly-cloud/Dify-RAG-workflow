# 非遗与文旅智能咨询系统：本机启动与测试指南

本文档说明如何在当前 Windows 开发机上启动并测试项目。

当前环境约定：

- 项目目录：`D:\2026\Septemper\RAG-dify-pro`
- Dify 运行方式：本机 Docker
- Dify 版本：`1.17.1`
- Dify 控制台：`http://localhost`
- 项目 PostgreSQL：Docker 容器 `app-postgres`，宿主机端口 `5433`
- 项目 Redis：Docker 容器 `app-redis`，宿主机端口 `6380`
- API：`http://localhost:3100`
- 管理后台：`http://localhost:3200`
- PC/移动网页咨询端：`http://localhost:3300`

## 1. 启动项目数据库

在 PowerShell 中执行：

```powershell
cd D:\2026\Septemper\RAG-dify-pro
pnpm install
docker compose --env-file .env -f docker-compose.app.yml up -d app-postgres app-redis
docker compose --env-file .env -f docker-compose.app.yml ps
```

这里只启动项目自己的 PostgreSQL 和 Redis，不会改动正在运行的 Dify 数据库。

项目本机不需要预装 PostgreSQL。`app-postgres` 是一个独立的 Docker 容器，数据保存在
`app_postgres_data` 持久化卷中。

## 2. 配置 Dify

打开 Dify 控制台：

```text
http://localhost
```

完成以下配置：

1. 在知识库页面的“服务 API”中创建 Knowledge API Key。
2. 导入 `dify/chatflow-generator.yml`。
3. 打开导入后的“非遗文旅咨询生成器”，将其中的 LLM 节点替换为当前工作区已配置的模型。
4. 发布 Chatflow。
5. 在应用的“访问 API”页面创建 App API Key。
6. 将两个 Key 写入项目根目录 `.env`。

需要配置的环境变量：

```dotenv
DIFY_API_BASE_URL=http://localhost/v1
DIFY_KNOWLEDGE_API_KEY=dataset-xxxx
DIFY_CHAT_APP_API_KEY=app-xxxx
```

目前 `.env` 中两个 Dify Key 默认为空：

- 只测试管理员登录和后台界面时，可以先不填写。
- 测试知识库创建、文档上传、索引状态、召回测试和问答时，必须填写。

## 3. 启动 Node 服务

分别打开四个 PowerShell 终端。

### 3.1 启动 API

```powershell
cd D:\2026\Septemper\RAG-dify-pro
pnpm dev:api
```

`dev:api` 会先构建共享包，再启动 NestJS API。

### 3.2 启动索引 Worker

```powershell
cd D:\2026\Septemper\RAG-dify-pro
pnpm dev:worker
```

Worker 用于轮询 Dify 文档索引状态，并更新数据库及 SSE 实时进度。

建议先启动 API，再启动 Worker。

### 3.3 启动管理后台

```powershell
cd D:\2026\Septemper\RAG-dify-pro
pnpm dev:admin
```

### 3.4 启动 PC/移动网页咨询端

```powershell
cd D:\2026\Septemper\RAG-dify-pro
pnpm dev:web
```

## 4. 访问测试

服务启动后可访问：

| 服务 | 地址 |
| --- | --- |
| 管理员后台 | `http://localhost:3200` |
| PC/移动网页咨询端 | `http://localhost:3300` |
| API 健康检查 | `http://localhost:3100/api/health` |
| Dify 控制台 | `http://localhost` |

管理员账号：

- 用户名读取 `.env` 中的 `ADMIN_USERNAME`，当前默认为 `admin`。
- 密码读取 `.env` 中的 `ADMIN_PASSWORD`。

API 健康检查返回以下内容，表示 API 和 PostgreSQL 已连通：

```json
{
  "status": "ok",
  "database": "ok"
}
```

## 5. 建议测试流程

1. 登录管理员后台。
2. 点击“新建知识库”。
3. 配置知识库名称、嵌入模型、分段规则和检索设置。
4. 上传 PDF、Word、TXT 或 Markdown 文档。
5. 在后台观察排队、解析、清洗、分段和索引过程。
6. 索引完成后查看真实分段。
7. 执行召回测试。
8. 发布文档。
9. 在 `http://localhost:3300` 选择该知识库并提问。
10. 检查回答中的来源引用。

## 6. 停止服务

在 API、Worker、管理后台和 Web 端对应的 PowerShell 终端中按：

```text
Ctrl+C
```

停止项目 PostgreSQL 和 Redis：

```powershell
docker compose --env-file .env -f docker-compose.app.yml stop app-postgres app-redis
```

## 8. 常见问题

### PostgreSQL 是否需要安装到 Windows？

不需要。项目使用 Docker Compose 启动独立的 `app-postgres` 容器。

### API 启动后无法连接数据库？

确认项目数据库已运行：

```powershell
docker compose --env-file .env -f docker-compose.app.yml ps
```

并检查 `.env` 中的 `DATABASE_URL`：

```dotenv
DATABASE_URL=postgres://heritage:dev-heritage-password@localhost:5433/heritage
```

### 知识库创建时提示 Dify 认证失败？

检查 `.env` 中的：

```dotenv
DIFY_KNOWLEDGE_API_KEY
```

该 Key 必须具有创建和访问全部知识库的权限。

### 用户端可以打开，但暂时不能问答？

检查以下配置：

```dotenv
DIFY_KNOWLEDGE_API_KEY
DIFY_CHAT_APP_API_KEY
```

同时确认以下服务正在运行：

- Dify API
- Dify Worker
- 项目 API
- 项目 Worker
- PostgreSQL
- Redis
